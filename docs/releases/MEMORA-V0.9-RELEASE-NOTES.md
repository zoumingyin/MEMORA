## 2. 本版重点

### 2.1 便签、待办与提醒

- 统一便签、待办、提醒三类内容，支持标题、正文、分类筛选和关键词搜索。
- 便签支持 Markdown 正文和常用格式编辑。
- 待办支持子任务清单与完成进度。
- 提醒支持多个闹钟；每个闹钟可设置单次或重复模式。
- 删除进入废纸篓，可恢复，也可彻底删除。
- 便签支持独立小窗查看与编辑；小窗可拖动、缩放并原地展开编辑。
- 主题支持浅色、深色和跟随系统；支持透明度、窗口置顶和边缘吸附设置。
- 关闭主窗口时隐藏到托盘，而不是直接退出进程。

### 2.2 AI 助手

- 支持对话查询、创建、修改和删除便签/待办/提醒。
- 创建和普通修改直接执行；删除必须经过 ActionCard 二次确认。
- 支持多轮上下文、活动任务、实体记忆和确定性指代解析。
- 长对话使用确定性摘要压缩，保留最近消息和当前用户输入。
- 支持多步骤任务清单，区分待执行、执行中、完成、失败、跳过和取消。
- 支持停止任务；停止后尚未开始的工具不会执行。
- 支持续办；已完成或状态未知的写操作不会自动重放。
- 最终结果摘要以真实工具执行记录为准，不由模型正文单独决定。
- 支持执行历史列表、详情、搜索、状态筛选、分页、单条删除和清空。

### 2.3 失败恢复

- 统一区分请求失败、工具失败、业务失败、状态未知、中断和跳过。
- 部分成功会保留成功步骤，并明确展示失败与未执行步骤。
- 写入结果不确定时要求用户核对真实数据，不自动重试写操作。
- 应用重启后，旧的删除确认卡片和闹钟选择授权失效。
- 重启后未完成的执行记录会被正确恢复为中断/未知状态，不会重放写入。

### 2.4 安全边界

- 查询结果只能作为候选，不能直接授权写入。
- 历史记录中的 ID 不能授权新的写入。
- 模型提供的 `alarm_id` 不构成用户授权。
- 多个闹钟目标不明确时必须询问用户，不自动选择。
- 同名或高相似目标不会自动写入。
- 删除提议必须由用户点击确认后才能移入废纸篓。
- 删除确认历史只回写真实结果，回写必须通过 `executionId + stepId + proposalId + targetId` 关联校验。
- 执行历史本身不是新的写入授权来源。
- 模型文本、便签正文或工具结果不能升级为系统指令。

### 2.5 修复

- 修复删除链接中“缺少 `proposal_id` 的旧步骤仍可能匹配回写”的问题。
- 修复删除工具兼容性问题：避免把标题同位语误判为未解析指代，避免取消后重新删除被旧历史强制只读。
- 修复执行阶段“部分成功被显示为全部失败”和“停止被显示为完成”的状态表达问题。
- 修复重启后残留的 `pending/running` 计划项未收敛的问题。
- 修复删除确认历史回写异常影响业务删除的问题。
